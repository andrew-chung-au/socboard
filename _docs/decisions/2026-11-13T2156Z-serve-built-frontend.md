# Decision: The app serves the built frontend with one fallback route registered last

One file per choice that may be revisited. **Status: proposed.** The human approves it with issue #140 (body hash `298e0fafb4da7c063dd9d87b850359c2f3877ae15e17f585fc2e0021fba75252`); only the human sets `approved`. Heavy tier: it adds a public interface to the app that fronts the case and audit data.

- **Decision:** The FastAPI app serves the built site from one setting, `SOCBOARD_STATIC_DIR` (default `frontend/dist` in the repository root). `socboard/spa.py` adds one GET (and HEAD) fallback route after every API router. As built, it has no separate static mount: the route returns a file that is inside the folder (after resolving symlinks and `..`), otherwise `index.html` for a path with no extension, otherwise a 404. It never matches `/api` or a path under it, so the existing JSON 404 and 405 are unchanged, and `/apix` is a screen route. Other methods on a screen route get the existing JSON 405. A missing folder, or one without `index.html`, adds nothing and is not an error. `index.html` and unhashed files are sent with `Cache-Control: no-cache`; files under `assets/` with `public, max-age=31536000, immutable`. No cookie is set.
- **Reason:** The spec asks for one origin and one image; the built site is static files, so no second web server is needed. Registering the fallback last, and making it ignore `/api`, means it cannot shadow or change an API answer. Treating dotted paths as files keeps a missing asset a 404 instead of an HTML page that a script tag would try to run. One route means one containment check for every file.
- **Alternatives:** A static mount for `assets` plus the fallback, as the issue's draft said (two code paths for the same folder, and a second place to get the containment check wrong); Caddy serving the files in front of the app; Starlette's `html=True` mode (falls back for directories only, not for client routes); a runtime settings file served by the app.
- **Trade-offs:** The app now serves files, so traversal and methods are its job (tests cover each). A client route containing a dot would be a 404. The folder is checked once, when the app is built. A set but empty value uses the default. Existing tests that request an unknown extension-less path outside `/api` (for example `/health`) expect the JSON 404 and would get the entry page on a machine where `frontend/dist` exists; CI has no `dist` when it runs them. Response security headers (`nosniff`, `frame-ancestors`, a content security policy) are left out on purpose because the issue puts them out of scope; a follow-up issue is proposed.
- **Evidence:** Issue #140 and its Decision record; `_docs/specs.md` section 4 (Deploy stories); `socboard/spa.py`; `tests/test_spa_serving.py`.
