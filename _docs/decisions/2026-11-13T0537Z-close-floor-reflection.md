# Decision: A reflection-only Engineer comment does not set the close floor (local deviation from the kit)

One file per choice that may be revisited. **Status: approved.** The human ruled on option 1 of issue #63 (recorded in the `PM:` comment of 2026-11-11T10:00:26Z) and approved the issue with the `approved` label (body hash `6bc8539fd7b88a44047c71cb57dc2e076242589e6b6dbb1c01c454181f3d3602`, matching `make issue-hash N=63`). The human approves the exact diff of the protected kit file before it is committed. Heavy tier: it changes the rule that gates every issue's closure.

- **Decision:** In `_docs/agent-kit/scripts/issue-close.sh`, an owner `Engineer:` comment does not set the floor when it has a `Reflection:` block and lacks the Engineer work-comment markers (a verify result and per-criterion lines). Any comment with those markers still sets the floor, with or without a reflection. Landed as a local deviation from the kit, with a note for upstream.
  - A `Reflection:` block is a line that starts with `Reflection:`.
  - The markers, taken from `team/software-engineer.md` and `procedures/verify.md`, are both of: a line that starts `Verify:` or `Verify result:` (bold allowed), and a numbered criterion line (`1.`, `1)`, `1:`, `Criterion 1:` or `AC1:`) that says `done`, `not done` or `not checked`.
  - Unchanged: owner-only comments, the two-QA-PASS rule for Heavy, the `QA PASS commit` check in the Close comment, the Light path, and the rule that a floor comment must say "commit" and hold 7 to 40 hex characters.
- **Reason:** It is the smallest change, keeps the evidence value of hashes in reflections, and keeps the floor's purpose (new work after QA PASS forces a re-check). A local deviation unblocks closures now.
- **Alternatives:**
  1. Exclude any comment containing a `Reflection:` block: simpler, but an Engineer comment with new work and a reflection appended would bypass the re-check.
  2. Floor from commits on the issue, not comment text: stronger, but needs a reliable link from commits to the issue, which the kit does not have (Kiro Web branches and PR merges differ).
  3. Tell roles not to cite hashes in reflections (`session-summary.md` only): no script change, but nothing enforces it and one slip blocks closure again.
  4. Upstream first, then import: shared fix, but closures stay blocked until it lands.
- **Trade-offs:** The work-comment markers must be defined precisely, and a work comment that omits them (a malformed one) would not move the floor if it also has a `Reflection:` block. A comment with no `Reflection:` block still moves the floor with or without markers, as before. The check relies on the Engineer comment layout in `team/software-engineer.md`: if that layout changes, the two patterns in `is_reflection` must change with it. A reflection that itself has a `Verify:` line and a numbered line ending in "done" would count as work (the safe direction: QA re-checks). As a local deviation it adds to the difference list and needs an upstream note.
- **Upstream note (feedback for the upstream kit):** `make issue-close` refuses every Standard or Heavy issue whose Engineer reflection (`procedures/session-summary.md`, Reflection) names a commit, because the floor takes any `Engineer:` comment with "commit" and a hex string. Suggest the upstream script adopt the same test (a `Reflection:` block without a `Verify:` line and numbered done/not-done/not-checked criterion lines is not new work), or define the Engineer comment markers in `team/software-engineer.md` so the script and the layout cannot drift apart. Until upstream does, keep this record as deliberate drift at the next kit import. `procedures/session-summary.md` needed no change: it says nothing that the rule contradicts.
