# Decision: Agents write a tool attribution line on every commit (local deviation from the kit)

One file per choice that may be revisited. **Status: proposed. The edited kit files are protected: the human approves the exact diff before they are committed.**

- **Decision:** Every agent commit message ends with one line, `Assisted-by: <Tool>` (Kiro, OpenCode or Claude Code), written by the agent. No co-author line with an email address, and no model name or version. This deviates from the kit's rule that attribution comes only from tool settings and that agents add no lines of their own. Three kit files change: `_docs/agent-kit/team/software-engineer.md` (Commits), `_docs/agent-kit/process.md` (Commits and pushes) and `_docs/agent-kit/blueprints.md` (Commit attribution, and its table row). Each edited line carries a comment pointing here. The kit version is not bumped: this is not the kit repo, this kit has no manifest and no version claim, and the change is a recorded deviation, not a new kit release.
- **Reason:** Roles move between tools as usage limits allow, so the tool behind each commit has to be readable from git. Tool settings do not cover all three tools. Kiro Web has no setting the kit knows of, although its commits carry the author `Kiro Agent`. OpenCode's default footer, as reported in its issue tracker, includes a co-author line with an email, which the kit's own blueprint avoids, and I could not confirm it for the installed version. One plain, uniform trailer written by the agent works the same everywhere and is easy to match by script.
- **Alternatives:**
  - *Keep the kit rule and rely on tool settings:* leaves the Kiro Web and OpenCode gaps.
  - *Accept OpenCode's default co-author footer:* includes an email, is unverified for the installed version, and the script would still have to tolerate it.
  - *Identify the tool by git author alone:* works for `Kiro Agent` only. Other tools commit under the human's identity.
  - *Record the tool only in the session summary:* not visible in git, so nothing to cross-check.
- **Trade-offs:** The rule is enforced by instruction, not by the tool. A weaker model may omit the line, so the metrics script cross-checks the `Launch usage` line and flags disagreements. The kit files now differ from upstream; at the next kit import the file is kept as deliberate drift and this record explains why. A tool that also adds its own line produces a harmless duplicate.
- **Evidence:** `git log` on 2026-11-06 showed Kiro commits with author `Kiro Agent`, while commits made through other tools carry the human's name and no marker. The diff of the three kit files is the change itself.
