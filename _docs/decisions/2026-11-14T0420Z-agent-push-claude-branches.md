# Decision: Let an agent push its own `claude/` work branch to `origin` (local deviation from the kit)

One file per choice that may be revisited. **Status: approved.** The human chose this option ("2 approved") in the #22 session on 2026-11-14, after the kit's push block stopped the push the human had asked for, and approved the exact diff of this record, the wrapper hook, the settings change and its test before they were committed.

- **Decision:** A project-owned Claude Code hook, `.claude/hooks/guard_git_local.py`, wraps the kit's `guard_git.py` and lets through exactly one command shape: `git push [-u|--set-upstream] origin claude/<name>`, alone in the command. `.claude/settings.json` runs the wrapper instead of the kit file. Every other push stays blocked (another branch, `main`, a force push, a delete, a refspec with `:` or `+`, `--all`, `--mirror`, `--tags`, `--no-verify`, another remote, a chained command), and the kit's other blocks are unchanged. `tests/test_guard_git_local.py` pins both sides. The tool's permission settings ask the human before every `git push` (an `ask` rule, not `deny`), so each push also needs the human's yes at the prompt. Before an agent pushes, it runs `make verify` and gets the human's go-ahead for that push in the session.
- **Reason:** In a cloud session the branch exists only in the container, which is reclaimed after inactivity, and the human cannot run `git push` there themselves (a `!` command sent from the Claude app arrives as chat text). Without a push the human cannot review the branch, open a pull request or run a by-hand check from their own clone. The cloud session's own git rules already limit agents to a `claude/` work branch.
- **Alternatives:**
  - *Edit the kit's `guard_git.py`:* makes the kit a derivative of its manifest (`make kit-check`) and drifts from upstream; the Reviewer role set the precedent of project-owned files outside the kit.
  - *The human pushes from a terminal attached to the session:* keeps "only the human pushes" whole, but was not available from the app.
  - *Push through the GitHub API (file uploads):* a way around the hook, which `AGENTS.md` forbids.
  - *Leave work unpushed:* risks losing it when the container is reclaimed and blocks review.
- **Trade-offs:** "Only the human pushes" now has an exception for `claude/` branches; `main` and every other branch stay human-only, and merging stays with the human. In this container `core.hooksPath` is not set, so the repository's pre-push hook (which runs **Verify**) does not run on push; the agent runs `make verify` before pushing instead, which is a process rule, not enforced. Like the kit guard, the wrapper is a guard against habits, not a security boundary: a command the parser cannot see through is not covered. `AGENTS.md` ("Enforced by hooks") and `process.md` still say only the human pushes; updating their wording is a separate protected change for the human to approve.
- **Evidence:** #22 session, 2026-11-14 (the kit hook's refusal "Don't push. The human reviews the diff and pushes"; the human's approval of option 2); `_docs/decisions/2026-11-10T0822Z-reviewer-role.md` (project-owned files outside the kit).
